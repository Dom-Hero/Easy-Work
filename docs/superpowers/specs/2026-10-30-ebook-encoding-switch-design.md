# 电子书阅读：编码切换并重新解码

日期：2026-10-30  
状态：已实现  
范围：新导入 txt 保留原文件；阅读页切换编码后整本重解

## 目标

阅读页增加编码选择。用户发现正文乱码时，改选 UTF-8、GBK/GB18030、UTF-16 LE 或 UTF-16 BE，整本书按该编码重新解析，并尽量停在同名章节继续阅读。

导入时仍自动检测编码。只有这次改动之后新导入的书会留下原文件。已经在库里的书没有原文，编码选择不可用，需要重新导入一次。

## 约束（已与产品确认）

| 项 | 选择 |
|---|---|
| 原文件 | 只为新导入成功的书保存；旧书不回溯 |
| 重解方式 | 在原书上替换章节和正文，不另存一本 |
| 重解范围 | 整本重解。章节标题也依赖解码结果 |
| 失败时 | 保留原来的正文和章节 |
| 刷新安全 | 重解过程不把书的 `status` 写成 `parsing`。刷新中途导入会被当成失败导入删掉，重解不能走这条路径 |
| 替换时机 | 新正文全部写成功后，再删旧正文、换章节目录 |

## 非目标

- 不为已导入的旧书找回原文件，也不在阅读页再选一次 txt
- 不在导入页增加编码选择
- 不支持 Big5、Shift-JIS 等其他编码
- 不保留乱码版本作为另一本书
- 不改沉浸翻页、文档窗口加载本身的规则

## 数据

`EbookBook` 增加两个可选字段，由 `normalizeBook` 原样保留，避免 `putBookMeta` 写回时丢掉：

| 字段 | 类型 | 说明 |
|------|------|------|
| `encoding` | `'utf-8' \| 'gb18030' \| 'utf-16le' \| 'utf-16be'` | 当前正文使用的编码。新导入和重解成功后写入 |
| `hasSource` | `boolean` | 为 `true` 表示原文件已写入本地库。缺省视为没有原文件 |

IndexedDB 升到版本 3，新增 `sources` 对象仓库，主键 `bookId`：

| 字段 | 类型 | 说明 |
|------|------|------|
| `bookId` | `string` | 与书 id 相同 |
| `blob` | `Blob` | 原始 txt 字节 |
| `fileName` | `string` | 导入时的文件名，重解时用来构造 `File` |

原文件不放进书的元数据。删除书时，同一事务里删掉对应的 `sources` 记录和现有正文。

## 解析

`parseEbookFile` 增加可选参数 `encoding`。传入时跳过 `detectTextEncoding` 和文件头采样，直接用 `createTextDecoder(encoding)`。不传时行为与现在相同。

## 导入

`importTxtFile` 在解析并写完正文、书变为可读之后，再保存原文件：

1. 原文件保存成功：写入 `encoding`（自动检测结果）和 `hasSource: true`。成功提示保持现在的「已导入「书名」（编码名）」。
2. 原文件保存失败（含空间不足）：书仍然导入成功，不写 `hasSource`。提示改为警告：「已导入「书名」（编码名），原文未能保存，无法在阅读页切换编码」。

解析失败或用户取消时不保存原文件。现有的失败清理继续调用 `deleteBook`，因此也会清掉可能已写入的原文件。

## 重解

`useEbookLibrary` 提供 `redecodeBook(bookId, encoding)`。

不重解的情况：

- 目标编码与 `book.encoding` 相同：直接成功，不写库。
- 已有一本书正在重解：返回「正在重新解析，请稍候」。
- `hasSource` 不为 `true`，或 `sources` 里没有这条记录：返回「这本书没有保留原文，请重新导入后再切换编码」。记录缺失时把内存和元数据里的 `hasSource` 清掉。

重解步骤：

1. 用保存的 `Blob` 和 `fileName` 构造 `File`，调用 `parseEbookFile(file, { encoding })`。
2. 新章节使用解析器新生成的 id，正文按现有分片方式写入。旧章节和旧正文先留着。
3. 进度只放在内存里的重解状态（当前书 id、0–100 的比例），不写入书的 `status` 或 `parseProgress`。
4. 解析结果为空，或写入失败：删掉这次新写下的分片，旧书不动。空间不足时提示「本地存储空间不足，原文未替换」；解析不出正文时提示「按该编码未能解析出正文」；其他失败提示「重新解码失败」。
5. 成功：清掉这本书在内存里的正文缓存，删除旧章节对应的正文记录，把书的 `chapters` 和 `encoding` 换成新结果并写入元数据。返回更新后的书。

刷新若发生在第 5 步之前，书仍指向旧章节，可以继续读。这次已写入的新分片会留在库里，直到删除该书。不做额外的孤儿分片清扫。

## 阅读页

编码控件放在顶栏模式切换左侧，并和模式切换一起靠右。窄屏下随顶栏换行。

可选值固定为：

| 值 | 文案 |
|----|------|
| `utf-8` | UTF-8 |
| `gb18030` | GBK/GB18030 |
| `utf-16le` | UTF-16 LE |
| `utf-16be` | UTF-16 BE |

- 有原文件：下拉显示 `book.encoding`。没有 `encoding` 时不预选，等用户选择后再重解。
- 没有原文件：下拉禁用，框内显示「需重新导入」。`title` 为「这本书没有保留原文，请重新导入后再切换编码」。
- 重解进行中：下拉禁用。文档模式和沉浸模式的阅读区都显示「正在按所选编码重新解析…」，不继续呈现旧正文。

`index.vue` 里的 `readerBook` 仍是打开时的快照，避免「最近访问」更新把目录抖掉。只有当前书的 `chapters` 或 `encoding` 变化时，才用库里的新书替换快照。

替换后的章节定位：

1. 记住重解前当前章节标题。
2. 在新目录里找标题完全相同的章节。
3. 找到就打开它，否则打开第一章。
4. 把 `activeChapterId` 设成该章的新 id，让阅读页按现有章节监听重新加载正文。

文档模式和沉浸模式都走同一套章节正文，不单独做解码。

## 验证

仓库没有单元测试脚本。实现后运行 `npm run type-check`，并在浏览器里核对：

1. 新导入一本书，顶栏编码与导入提示一致，正文可读。
2. 改成另一种编码后，正文和章节目录按新编码更新；再改回原编码，正文恢复。
3. 重解前停在某一章时，若新目录有相同标题，仍停在该章；标题对不上则回到第一章。
4. 重解失败或空间不足时，原来的章节和正文还在，并出现对应提示。
5. 本次改动前已导入的书，编码下拉禁用，并显示「需重新导入」。
6. 删除新导入的书后，该书不能再被打开；不留下可切换编码的空壳。
7. 文档模式和沉浸模式都能读到重解后的正文。
